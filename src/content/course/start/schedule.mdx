## The whole path

The course runs in eight parts, six architecture blocks and six projects. Architecture always arrives just before the project that needs it, and each project uses everything before it.

| Tier | Block | What you learn | Hands-on |
|---|---|---|---|
| 1 | Part 0 · Groundwork | tmux, git worktrees, the two schools | Terminal drills |
| 1 | Part 1 · One agent | The agent loop and its controls; your first skill | The lab repo |
| 2 | Architecture A1 | Components, data, boundaries, decision records | Design Pocket Ledger |
| 2 | Part 2 · The feature loop | Scope, architect, develop, verify, review, sync | Your own skills |
| 2 | **Project L1 · Pocket Ledger** | Everything so far, end to end | A deployed app |
| 2 | Part 3 · When things go wrong | Debugging, session recovery, inherited code | A real open-source repo |
| 2 | Architecture A2 | Threat models, auth, encryption, secrets | Threat-model Vault |
| 3 | Part 4 · A crew | Splitting work, coordination, roles, handoffs, security | Your first crew |
| 3 | **Project L2 · Vault** | Zero-knowledge design behind real gates | A password manager |
| 3 | Architecture A3 | Tenants, roles, jobs, caches, pipelines | Design Book-a-Slot |
| 3 | Part 4 continued | Review gates, testing, UI with agents | Gates on your repos |
| 3 | **Project L3 · Book-a-Slot** | A parallel crew on a multi-role product | Two frontends, CI/CD |
| 3 | Architecture A4 | Services, events, consistency, observability | Design Courier Live |
| 3 | **Project L4 · Courier Live** | A hierarchical crew on a distributed system | Three apps, two services |
| 4 | Part 5 · Many projects | Isolation, monitoring, incidents, overnight runs | Two live projects |
| 4 | Architecture A5 | Products that contain an agent | Design Support Copilot |
| 4 | **Project L5 · Support Copilot** | An AI feature, measured by evaluations | Built while L3 runs |
| 4 | Part 6 · Making decisions | Reversibility, trade-offs, stacks, pre-mortems | Decision drills |
| 4 | Architecture A6 | Offline sync, native vs cross-platform, IaC, compliance | Design your capstone |
| 4 | Part 7 · Your workflow | Choose, measure, improve and package your workflow | Your plugin |
| 4 | **Project L6 · Capstone** | Your product, your workflow, one month | Measured results |
| 4 | **Mastery exam** | Three unseen scenarios | Designs you defend |

## A realistic pace

The whole course is roughly **250 hours**, most of it hands-on. Here are three honest paces:

| Pace | Hours a week | Takes about |
|---|---|---|
| Steady | 8–10 | 7 months |
| Focused | 12–15 | 4–5 months |
| Intensive | 20+ | 3 months, but you'll retain less |

At the steady pace, a typical schedule looks like this:

| Weeks | Covers |
|---|---|
| 1–3 | Start here, Part 0, Part 1 |
| 4–6 | Architecture A1, Part 2 |
| 7–8 | Project L1 Pocket Ledger |
| 9–10 | Part 3, Architecture A2 |
| 11–13 | Part 4 (first half), Project L2 Vault |
| 14–17 | Architecture A3, Part 4 (second half), Project L3 Book-a-Slot |
| 18–21 | Architecture A4, crew run, Project L4 Courier Live |
| 22–25 | Part 5, Architecture A5, Project L5 Support Copilot |
| 26–27 | Part 6, Architecture A6 |
| 28–31 | Part 7, Project L6 Capstone (runs for a month) |
| 32 | Mastery exam |

## When life gets in the way

- **Missed a week?** Start with the review page at the end of the last Part you finished. It's short and it brings everything back.
- **Stuck on a project milestone for more than two sittings?** Each milestone has a "when it goes wrong" section. If that doesn't help, ask your agent to diagnose using the Part 3 debugging method, and write down what you learned.
- **Tempted to skip the architecture blocks?** Don't. They're where the course stops being "how to use agents" and becomes "how to decide what to build and how". The projects assume them.

<Callout type="brass" label="The one rule for pace">
  <p>Finishing fast is not the goal. Being able to explain every decision in your projects is. When in doubt, slow down and do the drill again.</p>
</Callout>
