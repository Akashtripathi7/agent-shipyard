## Recap

- **Architecture is the decisions that are expensive to change.** See components, boundaries and data flow; name the qualities that matter.
- **Start with a layered monolith.** Dependencies point downward; routes never contain SQL.
- **Design the API and the data model deliberately.** Money as integers, ownership on every row, constraints in the database.
- **Write load-bearing decisions as ADRs** and draw systems at the right zoom level.
- **State lives in files.** Clear context between steps; the spec is the handoff.
- **Scope challenges the idea** and cuts it into vertical slices.
- **Architect surfaces load-bearing decisions** and writes testable criteria. Only you approve.
- **Develop refuses unapproved specs,** builds test-first in small tasks, and stops to ask.
- **Verify proves real behaviour** with evidence; tests prevent regressions. You need both.
- **Review with fresh eyes, read-only.** Document from the diff. Sync keeps files honest.
- **Pick the entry point and depth per change.** Overrides for auth, money, personal data and deletion.

  <p>A criterion you can't test can't fail, which means it can't catch anything. Lesson 2.3.</p>
